# Домашнее задание к занятию «Репликация и масштабирование. Часть 1»
### Задание 1
Master-slave — это асимметричная архитектура, где запись данных происходит только на одном сервере (мастере), а один или несколько слейвов только читают данные и копируют их с мастера. Репликация идёт в одну сторону — только от мастера к слейвам. Это проще в настройке, но мастер становится единой точкой отказа: если он падает, запись данных становится невозможной.

Master-master — это симметричная архитектура, где оба сервера являются мастерами и могут принимать запись, при этом каждый из них одновременно является слейвом для другого. Репликация идёт в обе стороны — изменения с первого мастера копируются на второй и наоборот. Это сложнее в настройке и требует решения конфликтов при одновременной записи в одни и те же данные, но обеспечивает высокую доступность: если один мастер выходит из строя, второй продолжает принимать запись без простоев.

1. Направление репликации: в master-slave данные копируются только от мастера к слейву (однонаправленно), а в master-master — в обе стороны между серверами (двунаправленно).

2. Запись данных: в master-slave писать можно только на мастер, слейвы только читают; в master-master писать можно на оба сервера.

3. Отказоустойчивость: в master-slave при падении мастера запись останавливается; в master-master при падении одного мастера второй продолжает принимать запись.

4. Сложность: master-slave настраивается проще; master-master сложнее и требует дополнительных настроек для предотвращения конфликтов (например, разных диапазонов автоинкремента).

5. Риски: в master-slave — единая точка отказа для записи; в master-master — риск конфликтов при одновременной записи в одни и те же данные на обоих серверах.
